## Partly done

### Programme domain (template / instance / log)
- **P1** Progression rules: load progression and deload rules in the template. Only phases and +reps; load changes are suggestions, no rule editor, no deload

### Smart Schedule Engine
- **P1** Open an individual missed session and choose its resolution. Resolution is offered for all missed sessions together, not from one session
- **P2** Conflict resolution guidance beyond blocking (suggest alternative days). Conflicts block; only 'swap' is offered as a fix
- **P2** Multi-step re-synchronisation wizard. Single preview sheet

### Programme Builder
- **P1** Choose training days and rest days when creating. Days are auto-spread from 'sessions per week'; changeable per day afterwards, no explicit day picker
- **P1** Progression settings. Only 'add reps every N weeks'
- **P1** Per-week differences in a built programme. Pattern repeats identically; only imported/forked programmes edit week by week
- **P1** Preview weekly structure before saving. List of days; no week preview
- **P1** Multi-step builder with visible progress. One screen with auto-saved draft

### Calendar
- **P2** Rest-day detail. One line of text

### Migration and data
- **P1** V5 'saved plans' converted to runnable workouts. Kept view-only; structure not inspected

### Design system and shell
- **P2** Loading states without layout jumps. Skeleton component exists but is not used; screens render directly from local data

### Accessibility checklist
- **P1** Status is not shown by colour alone. Calendar dots rely on colour in the grid (names are in each day's label)
- **P1** Form errors tied to their fields. Sheet forms show a separate alert line, not linked with aria-describedby

### Onboarding
- **P2** Create-your-own path from onboarding. Offered later in Train
- **P2** Health Connect offered contextually. Only inside More > Health

### V5.0 capabilities to retain or improve
- **P1** Yoga, cardio, dance, step-board sessions run as workouts. Run from Train > Workouts; no dedicated sections or content for them
- **P1** Health trends and records per metric

### Security and Android continuity
- **P1** Avoid broad storage permission (use scoped access). MANAGE_EXTERNAL_STORAGE kept for the media folder
- **P1** Keep signing material out of the source. V5's debug keystore is committed; moving signing to repository secrets is in progress
