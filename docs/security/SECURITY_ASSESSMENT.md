# Security assessment: BeFyn V6.5

## Scope and method
Application source (`www/src`, `index.html`, CSS), Android configuration (patch scripts, Capacitor config, native plugins), dependencies (`package.json`), the CI workflow and scripts, secrets in the repository, data handling (storage, backup, import/export, migration), and the Health Connect, notification and media integrations. I investigated each finding, fixed it where real, and added a test or scanner rule so it cannot quietly return.

## Tools actually used (environment: Node v22.23.5, headless Chromium 157, no network, no Android SDK)
| Tool | Used for | Result |
|---|---|---|
| `tools/security-scan.mjs` (written for this project; dozens of rules) | secrets, dangerous APIs, CSP, Android settings, dependencies, CI workflow, data-protection rules | No blocking findings; accepted: keystore file (P2), all-files permission (P3), no lock file (P3) |
| Seeded self-test (`tests/security-scan.test.js`) | proves the scanner detects 17 planted problems (eval, innerHTML, hard-coded password, unsafe CSP, missing pipefail, debuggable, cleartext, SMS permission, old xlsx, git dependency, secrets file, WebView debugging, remote server) | Pass |
| Manual code review | injection and DOM sinks, URL handling, import paths, crypto, permissions, notification content | Findings V-07 to V-10 |
| Browser tests and a randomised UI test | script errors, layout, error states under hostile input (HTML, quotes, emoji, huge strings, path traversal text) | No application errors |
| `tests/ci/dry-run.sh` | build-configuration properties (non-debuggable, manifest settings) | 22/22 |

## Tools not run, and why
OWASP Dependency-Check and MobSF (need the NVD database and an APK), Semgrep and Gitleaks (not installed, no network), Android Lint, `npm audit` locally (no registry access). In their place the CI workflow runs `npm audit` with a gate (`tools/audit-gate.mjs`; an unreadable result is reported as "not audited", never as a pass) and the APK checks in `tools/verify-apk.sh`. Adding Gitleaks, Semgrep and MobSF as CI jobs is a sensible next step; I did not add them because I could not run or validate them here.

## Android permissions assessment (as generated by the patch scripts)
| Permission | Why | Verdict |
|---|---|---|
| `health.READ_STEPS`, `READ_ACTIVE_CALORIES_BURNED`, `READ_HEART_RATE`, `READ_SLEEP`, `READ_EXERCISE`, `READ_WEIGHT`, `READ_BODY_FAT`, `READ_HEIGHT`, `READ_OXYGEN_SATURATION` | Read-only Health Connect data, each requested per type with an explanation | Needed; read-only |
| `POST_NOTIFICATIONS` | Reminders, asked only when reminders are used | Needed |
| `VIBRATE` | Timer alerts | Needed |
| `READ_EXTERNAL_STORAGE`, `MANAGE_EXTERNAL_STORAGE` | Optional exercise-media folder (V5.0 feature) | Accepted risk (V-12) |
| `INTERNET` | Optional video thumbnails (Capacitor adds it by default) | Kept, low risk; cleartext is forbidden |
| Merged from plugins (for example `RECEIVE_BOOT_COMPLETED`, exact-alarm, `WAKE_LOCK`) | Local notifications | Reviewed in CI against a deny-list; unexpected ones raise a warning |
Never present (CI fails the APK): SMS, contacts, call log, phone state, camera, microphone, location, overlay, install packages, accessibility, `WRITE_EXTERNAL_STORAGE`.
Other settings: `allowBackup=false`, `usesCleartextTraffic=false` with a network security config, `debuggable false`, WebView debugging off, mixed content off, only `MainActivity` and the Health Connect permission-usage alias are exported by our patches. The merged manifest of the real APK has not been inspected (no APK).

## Data security summary
Stored on the phone only, no accounts or analytics. Backups are files you create (optionally AES-GCM protected). Imports are validated, size-limited and parsed without prototype pollution. V5.0 data is never deleted. The V5.0 vault has no default password. Residual risks are in the register (V-14 to V-17).

## Recommendation
No unresolved P0 or P1 security finding in source. Release is gated on the real build and APK checks (see the release notes).
